# cindywanady.github.io implementation plan

> For agentic workers: use superpowers:executing-plans to implement this plan
> task by task. Steps use checkbox syntax for tracking.

**Goal:** Build and deploy the two-practice personal site defined in the spec.

**Architecture:** Next.js App Router exported to static HTML, styled with
Tailwind v4 and Untitled UI's open-source components. All copy lives in typed
content modules validated by zod at build time, and every factual sentence
carries a verbatim quote from a committed source file.

**Tech stack:** Next.js 16, React 19, TypeScript 5.9, Tailwind 4, Untitled UI
React (CLI 0.1.x), zod 4, Vitest 5, Testing Library, Playwright 1.63,
`@axe-core/playwright`, `@typesafe-ai/sdk` 0.6.

**Spec:** `docs/specs/2026-09-24-site-design.md`. Read it first. This plan
argues from it and does not repeat its reasoning.

## Global constraints

- Static export only: `output: 'export'`, `trailingSlash: true`,
  `images.unoptimized: true`. No API routes, middleware or server actions.
- Light theme only. No `next-themes`, no dark-mode class ever applied.
- Palette hex values are exactly: `#7A263A #C96A4A #F28C7C #C89B2B #6F7A3A
  #D9C2A3 #F7F1E7 #4A3428`.
- Coral, mustard and sand are never text colors.
- Fonts: Familjen Grotesk (display, interface), Source Serif 4 (body).
- Copy rules (spec 5.5): first person, no em dashes, no emoji, sentences at
  most 20 words, American spelling, sentence-case headings.
- Banned patterns (spec 4.5): eyebrows, kickers, decorative counters,
  gradients, stat rows, glass cards, accent rails, emoji, animation other than
  the sequence strip.
- The only dependencies added beyond the starter's are zod, Vitest, Testing
  Library, jsdom, Playwright, `@axe-core/playwright`, `@typesafe-ai/sdk` and
  `tsx`. Starter dependencies that no shipped file imports are removed.
- npm's default cache in `~/.npm` has root-owned files on this machine. Run npm
  with `npm_config_cache` pointed at a writable directory; never `sudo`.

## Review focus

1. **A reader with a dark OS setting.** They must see the light theme. Covered
   by the Playwright `colorScheme: 'dark'` test in Task 9.
2. **A reader who prefers reduced motion.** Every strip step must be visible
   with no animation. Covered in Task 9.
3. **A narrow phone, 320 to 375px.** No horizontal scroll; the strip turns
   vertical. Covered in Task 9 at 320px and 375px.
4. **A claim whose quote drifts after the CV is edited.** The build must fail
   rather than ship an unsupported sentence. Covered by the evidence test in
   Task 3, which re-reads the source file on every run.
5. **A keyboard-only reader.** Every link and button reachable with a visible
   focus ring, skip link first. Covered in Task 9.

import { describe, expect, it } from "vitest";
import { checkEvidence, normalize, numbersIn, type Claim } from "@/lib/claims";

const src = { cv: "Led CRM platform migrations covering est. 50,000 records across 5 modules.", yoga: "Practicing for 3 years." };

describe("numbersIn", () => {

describe("normalize", () => {

        expect(normalize("it’s  a\nlucky ✨ day")).toBe("it's a lucky day");
    });

        expect(checkEvidence([c], read)).toEqual([]);

    it("fails a number in the text that the quote does not contain", () => {
        const c: Claim = { text: "I migrated 60,000 records.", source: "cv", quote: "est. 50,000 records" };
        expect(checkEvidence([c], read)[0].problem).toBe("number-not-in-quote");

### Task 6: Sequence strip

**Files:**
- Create: `src/components/site/sequence-strip.tsx`,
  `src/styles/sequence-strip.css`, `tests/unit/sequence-strip.test.tsx`

**Produces:**

```tsx
type Step = { label: string; detail?: string };
export function SequenceStrip(props: { title: string; steps: Step[]; tone: "data" | "yoga" }): JSX.Element;
```

Renders `<figure>` with a visible `<figcaption>` title and an `<ol>` of steps.
Each `<li>` holds the step label and optional detail. The joining rule is a
pseudo-element colored `--color-data` or `--color-yoga`. On entering the
viewport (IntersectionObserver, once) the host gets `data-drawn`, and CSS
transitions the rule's `scale-x` and each step's opacity with a per-step delay.
Under `prefers-reduced-motion: reduce` there is no transition and every step
is fully visible. Below 640px the list is vertical.

### Task 10: Claim check with TypeSafe

**Files:**
- Create: `scripts/claims.ts`, `src/lib/claim-verdict.ts`,
  `tests/unit/claim-verdict.test.ts`

**Produces:**

```ts
export type Relation = "supports" | "contradicts" | "says_nothing";
export type Verdict = "verified" | "contradicted" | "unsupported" | "review" | "fabricated";
export function verdictFor(relation: Relation, confidence: number, threshold?: number): Verdict;
```

`scripts/claims.ts` runs `checkEvidence` first and marks failures
`fabricated`. For the rest it asks TypeSafe one choice question per claim
through `@typesafe-ai/sdk` (confirm the call shape in its README before
writing), writes any `review` verdicts to `claims-review.md`, and exits
non-zero on anything other than `verified`. Without `TYPESAFE_API_KEY` it
exits 2 with a message naming the variable.

  0.7 is review; contradicts at 0.9 is contradicted; says_nothing at 0.85 is
